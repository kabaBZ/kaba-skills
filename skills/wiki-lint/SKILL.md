# 文档健康检查

用于整理关联关系以及排错（Lint），整理有价值的总览（overview）和对比（comparison）。

## 核心职责

1. 扫描 wiki，找出：
   - 页面间明显矛盾
   - 明显过时的表述（被新资料推翻）
   - 孤立页面（没有入链）
   - 被多次提到但没有独立页的概念
   - 严重缺失 cross-ref 的地方
2. 生成“建议清单”，不直接大改：
   - 哪几页建议合并 / 拆分
   - 哪些观点需要确认更新
   - 哪些概念值得单独开页
3. 经用户确认后再动手，并记录到 `wiki/log.md`：

```md
## [2026-04-08] lint | merge 概念_X v1→v2
```

## 工作方式

当用户调用 `/wiki-lint` 时：

1. 扫描用户指定范围；若未指定，默认检查 `wiki/`。
2. 优先产出结构化问题清单与建议，不直接做大规模修改。
3. 如果发现可以沉淀为总览页或对比页的高价值主题，单独列为建议项。
4. 仅在用户明确确认后，才执行合并、拆分、批量补链、统一重写等改动。
5. 执行改动后，更新 `wiki/log.md` 记录本次 lint 行为。

## 模式约定

### audit mode

- 只扫描、只报告、只给建议。
- 不直接修复页面。
- 适合被上层工作流在 digest 完成后统一调用。

### repair mode

- 只在用户已经明确确认后执行。
- 可根据用户选择的建议项或范围执行修复。
- 执行修复后更新 `wiki/log.md`。
- 若修复动作将造成较大范围重写，仍应先清楚说明范围。

## 输出要求

- 先报告发现，再给建议。
- 每条建议尽量附带涉及页面与原因。
- 默认保持保守，不做未经确认的大范围重构。
- 在 audit mode 下，输出应适合上层工作流直接拿来询问用户是否修复。
